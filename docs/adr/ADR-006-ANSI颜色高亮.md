# ADR-006 · ANSI 颜色高亮（M10）

## 状态
已采纳（M10）

## 背景
M1~M9 的地图一直是以 ASCII 字形（`@ # . ! > M m ~ ?`）画在终端里的纯文本，可读性靠「位置 + 字形」。
蜘蛛侠是红蓝战衣的视觉 IP，但黑白的 `@` 在满屏 `# .` 里并不出彩。M9 接力时把 ANSI 颜色高亮列为了
下一步候选（与光照衰减并列）。ADR-005 当时给它的定位是「表现层，纯 ASCII 门禁里难以机器判定」——
但也正因为只是表现层，它对既有规格零侵入，是最省心、最出彩的那个。

约束与 M6~M9 同款：
- 熔断②禁止改/删测试凑绿 ⇒ 既有 245 例不能破；
- 不变量 #1/#2 ⇒ 任何新增随机都会让同 seed 的既有回放全部作废；
- 不变量 #8 渲染纯净性 ⇒ `render()` 不改写游戏状态。

## 决策
- **颜色是「纯展示层」，不挂 `Game` / 不进 `render()`**：
  这是与 `fov` / `stealth` / `noise` 最关键的区别。后三者改变「**显示什么**」
  （迷雾遮住、感知决定警报），是玩法开关 ⇒ 挂在 `Game`；颜色只改变「**怎么画**」，字形本身不变
  ⇒ 属于展示层，留在 `main.py` + `src/rogue/color.py`。
  因此 `render()` 的输出保持原样，既有 245 例规格与三条演示**逐字节不变**
  （除外层包裹的转义码）。这是本次能「零风险落地」的根本原因。
- **`colorize(text, enabled)` 是 `render()` 之外的纯函数**：
  只包裹「已知字形」（`@ M m ~ ? ! > #`），空格 / 换行 / 未知字符原样透传，
  **剥离转义码后 == 原文本** ⇒ `assertIn("@", render())` 类既有断言全部成立；
  纯函数、零随机、确定性（不变量 #2 的精神）。
- **默认 TTY 自动上色，管道降级**：
  `should_color()` 在「标准输出是终端」时返回 True，否则返回 False。于是
  `python main.py` 在终端里出彩；`python main.py > log.txt` 落地的是纯文本，
  不污染日志 / diff（M6 的回归实证就靠 `grep "^-- "`，零影响）。
- **遵守 no-color.org**：设了 `NO_COLOR`（任意值）强制无色；`FORCE_COLOR` / `CLICOLOR=1` 强制有色。
- **`--color` / `--no-color` 显式开关**：与项目「新能力显式 opt-in」的哲学一致；
  CI / 重定向场景下可强制纯文本。
- **只给地图网格上色**：图例（中文说明）、状态栏（HP / 背包 / 潜行 / 听觉提示）保持原样，
  避免把 ANSI 码套到中文文本上导致终端显示错乱；颜色只为「区分地图元素」服务。
- **玩家 `@` 着红色**：呼应红蓝战衣的红色主调；敌人用品红区分，避免敌我同色。
  调色板在浅色 / 深色背景都尽量可读（`.` 地板 / ` ` 未探索保持默认色，不强制上色）。

## 后果
- 优点：蜘蛛侠在终端里第一次「活」了起来——红衣 `@`、品红敌人、黄补给、绿楼梯、青蜘蛛感应、
  蓝听声怪，一眼可分；且对既有 245 例规格与三条演示零侵入（门禁四道门全绿，测试 245 → 260）。
- 取舍：
  - 颜色只按「字形」上色，无法区分「当前可见的 `.`」与「记忆里的 `.`」——那是**光照衰减**（M11 候选）
    的职责，本单不做（验收 C）；
  - 未做红蓝双色描 `@`、按怪物类型分色等进阶配色（验收 C），一次性消耗已足够支撑「终端出彩」这一件事；
  - 颜色是第四条「展示通道」，刻意**不新增玩法开关**，也不与 `fov`/`stealth`/`noise` 三条链耦合；
  - 光照衰减仍是下一步候选（见 CLAUDE.md 当前里程碑）。
