# ADR-022 · 存档 / 读档（M26）

## 状态
已采纳（M26）

## 背景
M1~M25 把游戏做成能在真实窗口手动玩、有 Boss 与胜利闭环的完整蜘蛛侠 Roguelike，但**状态不持久化**——
关掉终端即丢，想留着进度 / 想从某一层接着打都做不到。交接文档（HANDOFF-T001，下一步候选②）把「存档 / 读档」
列为后续里程碑，用户据此要求实现。

约束与 M1~M25 同款：
- 不变量 #1/#2 ⇒ 任何新增随机都会让同 seed 的既有回放作废；存档不能引入新随机；
- 不变量 #8 渲染纯净性 ⇒ 视图层不改写游戏状态；
- 熔断②禁止改/删测试凑绿 ⇒ 既有 564 例不能破；
- 项目一贯哲学：新能力默认 opt-in，不加参数时与上一里程碑逐字节一致。

## 决策
- **存档 = 完整状态快照（而非重放输入序列）**：`Game.to_dict()` 导出「seed + PRNG 内部状态 + 全部玩法状态」，
  `Game.apply_state()` 原样恢复，`Game.from_dict()` 重建新实例，`Game.save/load` 走文件，
  `Game.load_into(path)` 原地读档（交互模式不更换对象引用，Renderer / 交互循环随之刷新）。
  - 选择快照而非「只存 seed + 输入序列重放」：快照能精确恢复 fov/light/switch 等衍生状态，**读档即原地还原**，
    无需重放整段输入，且对所有开关状态一致；重放方案需记录每一帧输入并重新模拟，脆弱且慢。
  - PRNG 内部状态（`random.Random.getstate()`）随快照保存，是「读档后续演化与并行推进一致」的关键（#1/#2）。
- **确定性导出**：坐标集合转列表后 `sorted`，`dict` 项转 `(list(key), value)` 后 `sorted`，文件用
  `json.dump(sort_keys=True)` ⇒ 同状态永远导出同一字节、往返零漂移、`from_dict(to_dict())` 幂等。
- **opt-in 默认关闭**：游戏照常运行不会触发任何存读档；只有玩家按 `S`（`_handle_key` 大写）或显式
  `Game.save()` 才写盘。小写 `s`/`l` 仍是移动键，不冲突。不加任何参数时与 M25 逐字节一致。
- **不碰内核**：存读档只在 `Game` 上做「状态快照 ↔ 文件」搬运，复用既有实体（`Monster.to_dict/from_dict`），
  不调用任何随机、不写任何玩法状态（`#1/#2/#8` 延伸）。`RandomSource` 仅新增 `get_state/set_state` 这对
  读写内部 PRNG 状态的纯方法（仍只在 `rng.py` 内接触 `random` 模块，#1 不破）。

## 后果
- 正向：玩家可随时存档、关掉后再读档接着玩；确定性保证读档不是「近似还原」而是「逐字节同态」。
- 负向/成本：存档文件是完整 JSON（含 rng 内部状态 625 个整数 + 整张地图），体积较大但可接受；
  格式带 `version`，未来如需字段迁移可在 `from_dict` 做前向兼容。
- 不变量 #26 新增：把「存档→读档逐字节同态 + 读档后续演化与并行推进一致」显式钉成机器可判定项
  （`tests/test_save.py`），与 #8/#9/#10 等同属「行为不变量」，由单元测试而非 seed-guard 判定。

## 替代方案（已权衡）
- 只存 seed + 输入序列重放：理论更「轻」，但需记录并忠实重放每帧输入、无法保留衍生状态快照的精确性，
  且对交互模式不友好（要回到存档点需重跑整段），故弃用。
- pickle 序列化：实现更短，但不可读、跨版本脆弱、且绕过「确定性导出」审计；项目一贯偏好明文可审查，故用 JSON。
