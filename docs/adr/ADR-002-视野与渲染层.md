# ADR-002 · 视野 / 渲染层（M6）

## 状态
已采纳（M6）

## 背景
M1~M5 的 `render()` 是「全图可见」——整层连走廊带怪物一起铺在屏幕上。ADR-001 曾把渲染层
列为后续工作。到 M6 需要补上探索感，但有两个硬约束：
1. 熔断②禁止改/删测试凑绿 ⇒ 既有 79 例规格（尤其 `test_level.py::test_render_shows_stairs`）
   断言「全图可见」，新能力不能把它们打破；
2. 不变量 #2 回合确定性 ⇒ 视野消耗 `RandomSource` 就会扰动战斗/掉落/生成的随机序列，
   同一 seed 的既有回放全部作废。

## 决策
- **视野默认关闭，显式 opt-in**（`Game(..., fov=True)` / `Game.procedural(rng, depth=1, fov=True)`）。
  与 M5 的「教学图默认、程序化显式开启」同一哲学：新能力不改写既有规格。
- **视野纯几何、零随机**：`src/rogue/fov.py` 只用 Bresenham 射线 + 半径 + 房间照明，
  不引入随机模块、不消耗 `RandomSource` ⇒ 开不开视野，玩法结果完全一致。
- **射线法而非 shadowcasting**：地图 33×17、半径 8 ⇒ 每帧约 200 条线，开销可忽略；
  代码可读、便于门禁审查。规模变大再换（工单 T-006 验收 C）。
- **进房间点亮整间**：复用 M5 的 `Game.rooms`，玩家所在房间无视半径全部点亮，
  避免「站在房里却看不见房角」的割裂感。
- **记忆只留不动的东西**：地形 / 楼梯 / 道具进记忆，怪物不进（怪物会跑，记忆会骗人）。
- **蜘蛛感应（Spider-Sense）**：4 格切比雪夫、**穿墙**感知，只画 `?` 轮廓；
  半径刻意小于视野半径 8，是预警不是透视——契合 MCU 荷兰弟版设定。
- **新增不变量 #8**：`render()` 不改写任何游戏状态，唯一例外是记忆集合单调增长。

## 后果
- 优点：探索感到位；既有 79 例规格零改动全绿（现 121 例）；演示 `python main.py`
  在同一 seed（19）下回合数与结局与 M5 完全一致，实证视野没有扰动随机序列。
- 取舍：
  - 两套渲染路径（`_render_full` / `_render_fog`）需要同时维护；
  - 演示脚本的寻路 AI 仍「知道全图」（它是演示脚本不是玩家），画面上会出现
    「蜘蛛侠朝未探索处走」的观感——视野只影响渲染，不影响 AI；
  - 纯 ASCII 无颜色 ⇒ 已探索与当前可见在屏幕上没有视觉区分（都用 `.` / `#`），
    只能靠「怪物是否在画」间接判断。上颜色需等验收 C（ANSI 高亮）。
