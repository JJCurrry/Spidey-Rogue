# T-017 · 环境光照场与完整光照场分离（M17）

## 一入一出（In/Out）
- **入**：M11 把「光」做成了环境层（`light_field`：房间中心固定灯 + 玩家随身微光），M12 追加随身手电、
  M13 用它按目标格光照算玩家视野半径、M14/M16 让房间灯可关/可碎。但 `light_field` 一直把
  「静态环境照明（房间灯）」和「玩家随身光源（微光/手电）」**混在同一份场里**。
  接力棒给 M16 的候选方向之一正是「环境光照场与完整光照场分离（复杂度翻倍、收益有限）」——
  把「只看环境光」的场单独拆出来，便于未来按需对二者分别取用，而不必每次都从完整场里抠。
- **出**：一套**纯几何、零随机**的「环境光照场 / 完整光照场」双场分离——
  1. 复用 `light` 开关（不新增开关）：M17 只在 `light=True` 时有意义；`light=False` ⇒
     两份场都清空，`ambient_level_at` / `light_level_at` 恒返回「明亮」，M1~M16 一字节不变。
  2. `Game.update_light()` 同源、幂等重算两份场：
     - `ambient_field` = 仅房间中心固定灯（不含玩家微光 / 随身手电），代表楼层**静态环境照明**；
     - `light_field`   = 房间灯 + 玩家微光 + 随身手电，即原有**完整场**（行为不变）。
  3. 新增 `_ambient_sources()`（房间灯集合，跳过 `switched_lights`/`destroyed_lights`）与查询入口
     `ambient_level_at(x, y)`（与 `light_level_at` 对称；光照关闭恒「明亮」）。
  4. **默认所有消费点仍走完整场（`light_field` / `light_level_at`）**——M11 怪物感知、M13 玩家视野、
     `colorize` 渲染梯度全部不变 ⇒ 行为零回归（gate 432 → 443，演示逐字节一致）。
  5. `render()` 字形一字不差（分离只新增只读查询，不改光照场的使用方）；`light=False` 时两份场皆空 ⇒ 既有例零侵入。

## 委托级别

  无外部依赖、复用 M11 的 `light_field` 与 `Room.center` 机制。

## 验收分级
- **A（必过，门禁）**：`tests/test_ambient_light.py` 全绿——
  - 分离是**纯几何、零随机**：两份场都不引入随机模块、不消耗 `RandomSource`（seed-guard 仍只放行 `rng.py`）。
  - 环境场**不含**玩家微光 / 手电：走廊近处在完整场被微光照亮、在环境场仍全黑（`TestAmbientExcludesPlayerLight`）。
  - `ambient_field` 严格等于「仅房间灯」算出的场（定义即契约，`TestAmbientMatchesRoomOnlyField`）。
  - 关灯 / 碎灯从**两份场同时**移除房间光源（只移除不新增，`TestSourceRemovalFromBothFields`）。
  - 确定性：同 grid + 同房间 + 同玩家 ⇒ 同环境场；`update_light` 幂等（`TestAmbientOffAndDeterminism`）。
  - **行为零回归钉死**：M13 `update_fov` 用的是完整场而非环境场（`TestUpdateFovUsesFullField`）；
    M11 怪物感知仍走 `light_level_at`（完整场，`TestMonsterPerceptionUnchanged`）⇒ 不变量 #9 硬性质不破。
  - `python scripts/gate.py` 四道门 ALL GREEN，棘轮 432 → 443。
- **B（建议）**：`python scripts/balance_check.py` 默认 30/30、潜行 28/30（不变）；
  `python main.py` 与 `--stealth` 与 `--light --stealth` 与 `--flashlight` 四条演示均通关（与 M16 逐字节一致）。
- **C（可选，明确留作后续）**：把「怪物感知改用环境场（仅房间灯 + 手电，不含被动微光）」作为可选项——
  让蜘蛛侠的随身微光只帮自己看路、不再被动把附近暗处的怪「照」成近视眼的反面（被微光照亮的怪反而看得更远）；
  该改动会改变 M11 平衡，需重跑 `--light` / `--flashlight` 演示确认仍通关，**不在 M17 默认开启**。

## 范围边界
- **M17 只做分离、不改玩法**：`light_field` 仍是 M11/M13/渲染的唯一消费场，`ambient_field` 仅暴露查询接口
  （`ambient_level_at`）。任何「改用环境场」的玩法改动都是 C 级后续项，不默认启用。
- **两份场同源**：都由 `update_light()` 在 `light_enabled` 时重算；`load_level`/`descend`/开关灯
  都经 `update_fov` → `update_light` 重算两份 ⇒ 换层与光操控后两份场同步刷新，无陈旧场。
- **关灯 / 碎灯同时影响两份场**：`_light_sources` 与 `_ambient_sources` 都跳过 `switched_lights`/`destroyed_lights`
  ⇒ 两份场都「只移除光源、不新增」⇒ 光照场只变暗不变亮 ⇒ #9/#12/#14 不破。
- **只缩短不放大**：环境场不含微光/手电，不代表它更亮；完整场含微光只可能更亮（玩家看得更清），
  与「暗处近视」的既定语义无冲突。

## 不变量增量
- **#17 环境场与完整场分离**：环境光照场（`ambient_field`，仅房间灯）与完整光照场（`light_field`，房间灯 + 玩家微光 + 手电）
  由同一 `update_light()` 纯几何、零随机、幂等重算；默认所有玩法/渲染判定走完整场（行为零回归），
  环境场仅作为「只看静态环境照明」的查询入口对外暴露；`light=False` 时两份场皆空、查询恒「明亮」。
