# T-010 · ANSI 颜色高亮（M10）

## 一入一出（In/Out）
- **入**：M1~M9 的地图一直是以 ASCII 字形（`@ # . ! > M m ~ ?`）画在终端里的纯文本，
  可读性靠「位置 + 字形」。蜘蛛侠是红蓝战衣的视觉 IP，但黑白的 `@` 在满屏 `# .` 里并不出彩，
  玩家要在一堆相似字符里靠脑补区分「我 / 敌人 / 补给 / 楼梯」。M9 接力时把 ANSI 颜色高亮列为了
  下一步候选（与光照衰减并列），因为它「是表现层，纯 ASCII 门禁里难以机器判定」——但也正因为只是
  表现层，它对既有规格零侵入。
- **出**：一套**纯展示层**的 ANSI 着色——把 `render()` 产出的每个字形按类型套一层 ANSI 转义码：
  `@` 红（红蓝战衣）、`M`/`m` 品红（已察觉 / 未察觉的敌人）、`~` 蓝（听见动静）、`?` 青（蜘蛛感应）、
  `!` 黄（补给）、`>` 绿（楼梯）、`#` 暗灰（墙）。**字形本身一个都不改**，只是外加颜色，
  因此 `assertIn("@", render())` 这类既有断言零风险（不变量 #8 渲染纯净性的延伸：render 输出零改动）。
  默认在终端（TTY）自动上色，管道 / 重定向 / 设了 `NO_COLOR` 时自动降级为纯文本，亦可用
  `--color` / `--no-color` 强制。

## 委托级别
- **S（自主完成）**：范围清晰（一个着色纯函数 + main.py 三处打印包裹 + 一组测试）、红线明确
  （#8 渲染纯净性延伸：render 输出零改动、不引入随机）、无外部依赖、完全复用既有 `render()` 字形。

## 验收分级
- **A（必过，门禁）**：`tests/test_color.py` 全绿——
  - `colorize(text, enabled=False)` **原样返回**；`enabled=True` 时只包裹「已知字形」，
    空格 / 换行 / 未知字符原样透传 ⇒ **剥离转义码后 == 原文本**（既有的任何 `render()` 断言都成立）。
  - `colorize` 是**纯函数、零随机、确定性**：同输入 ⇒ 同输出（不变量 #2 的精神）。
  - 对真实 `Game.render()` 的输出上色后：仍 `assertIn("@", ...)`，且剥离转义码 == 原 `render()`
    ⇒ 既有 245 例规格全部不受影响。
  - `should_color` 遵循 https://no-color.org ：设了 `NO_COLOR` 强制无色；`FORCE_COLOR` / `CLICOLOR=1`
    强制有色；否则按「标准输出是终端」自动判断。
  - `python scripts/gate.py` 四道门 ALL GREEN，棘轮 245 → 255+。
- **B（建议）**：`python main.py` 在终端里地图带上颜色；`python main.py > log.txt` 落地的是纯文本
  （颜色只在 TTY 时套上，日志 / diff 不受影响）。图例与状态栏文字不上色（只给地图网格上色）。
- **C（可选）**：按地形/可见性做更细的明暗（如记忆区比当前可见区暗）、按怪物类型分色、
  红蓝双色描 `@`、把颜色做成可配置主题。

## 范围边界
- **不进 `Game` / `render()`**：这是与 `fov` / `stealth` / `noise` 最关键的区别——
  后三者改变「**显示什么**」（迷雾遮住、感知决定警报），是玩法开关 ⇒ 挂在 `Game`；
  颜色只改变「**怎么画**」，字形本身不变 ⇒ 属于展示层，留在 `main.py` + `color.py`。
  因此 `render()` 的输出保持原样，245 例既有规格与三条演示**逐字节不变**（除外层包裹的转义码）。
- **不引入任何随机**：着色是纯函数（字形 → 颜色查表），不消耗 `RandomSource`，不读游戏状态以外的东西。
- **不改 `fov` / `stealth` / `noise` 任一开关**：颜色是第四条「展示通道」，不新增玩法开关，
  也不与既有三条链耦合。
- **只给地图网格上色**：图例（中文说明）、状态栏（HP / 背包 / 潜行 / 听觉提示）保持原样，
  避免把 ANSI 码套到中文文本上导致终端显示错乱。

## 不变量摘录（落 M10）
- #8 渲染纯净性（延伸）：`render()` 的输出**一字不差**；颜色是 `render()` 之外的纯函数包裹，
  不改写 `grid` / 实体 / HP / 任何游戏状态，也不改变字形。
- #2 回合确定性（精神）：`colorize` 是确定性纯函数（查表），同输入同输出；不消耗随机、不影响回放。
- #1 随机仅经 `RandomSource`：`color.py` 不引入任何随机调用（seed-guard 仍只放行 `rng.py`）。

## 常量表
| 常量 | 值 | 含义 |
|---|---|---|
| `RESET` | `"\033[0m"` | 重置转义，每个着色字形后复位，避免颜色串色 |
| `GLYPH_COLORS` | 字形→ANSI 前缀的字典 | `@` 红 / `M` 品红 / `m` 暗品红 / `~` 蓝 / `?` 青 / `!` 黄 / `>` 绿 / `#` 暗灰 |
| （未列：` `.` 地板 / ` ` 未探索） | 保持默认色 | 任何主题下都可读，不强制上色 |

## 设计决策
| 决策 | 选择 | 理由 |
|---|---|---|
| 颜色放展示层，不挂 `Game` | 是 | `fov`/`stealth`/`noise` 改变「显示什么」⇒ 玩法开关；颜色只改变「怎么画」⇒ 纯装饰。放 Game 会让 `render()` 输出带转义码，任何 `assertEqual(render(), ...)` 类精确断言都要改；放展示层则 `render()` 输出零改动，245 例零风险 |
| `colorize` 是 `render()` 之外的纯函数 | 是 | 只包裹已知字形，剥离转义 == 原文本 ⇒ 既有断言（含 `assertIn`）全部成立；纯函数易测、确定性 |
| 默认 TTY 自动上色，管道降级 | 是 | `python main.py` 在终端里出彩；`python main.py > log` 落地纯文本，不污染日志 / diff（M6 的回归实证就靠 grep 动作日志，零影响） |
| 遵守 NO_COLOR | 是 | 尊重 https://no-color.org 约定：设了 `NO_COLOR` 强制无色；`FORCE_COLOR`/`CLICOLOR=1` 强制有色 |
| `--color` / `--no-color` 显式开关 | 是 | 与项目「新能力显式 opt-in」的哲学一致；CI / 重定向场景下可强制纯文本 |
| 只给地图网格上色 | 是 | 图例 / 状态栏是中文文本，套 ANSI 易在部分终端错乱；且颜色只为「区分地图元素」服务 |
| 玩家 `@` 着红色 | 是 | 呼应红蓝战衣的红色主调；敌人用品红区分，避免敌我同色 |
