# T-021 · 可键盘操作玩法（M21）

## 一入一出（In/Out）
- **入**：用户明确「这个游戏需要真正可键盘操作的玩法，并且要能在开发到一定程度后自己游玩来测试」。
  此前 `main.py` 只有脚本自动驾驶 demo（`_player_act` 写死的寻路 AI，用于回归与演示，不能手动玩）。
  接力文件里 M20 是最后一条已登记里程碑，M21 内容由用户现场定为「可键盘操作」。
- **出**：一套**纯几何、零随机**的交互控制层，挂在既有 `Game` 方法之上——
  1. `main.py` 新增 `_handle_key(game, key) -> (acted, msg)`：把一个按键解析为玩家动作；
     撞怪即攻击（bump-to-attack）、`g` 拾取、`1~5` 用背包道具、`e` 蛛网摆荡突袭（M7）、
     `f` 随身手电开关（M12）、`>` 下潜、`空格/./回车` 等待、`?` 帮助、`q` 退出。
  2. `main.py` 新增 `_player_interactive(game, color_on, get_key=input, echo=print)` 键盘主循环：
     渲染 → 读键 → 执行 → `monster_turn()`，正确判定 胜利 / 失败 / 退出。
  3. `main()` 新增 `--play` 开关：进入交互模式；**默认（无 --play）仍走 `_player_act` 自动驾驶 demo**（行为零回归）。
  4. `tests/test_interactive.py` 15 例：动作映射 + 循环结局 + 确定性，注入式 `get_key` 模拟（不依赖真实 stdin）。

## 委托级别
- **S（自主完成）**：范围清晰（main.py 内新增三个函数 + 一组测试，不碰 `src/rogue` 既有逻辑）、
  红线明确（#1 零随机 / #2 确定性 / #4 不穿墙角 / #8 渲染纯净）、无外部依赖、
  完全复用 M1~M20 已落地的 `Game` 方法，是「让游戏能手动玩」这一用户诉求的落地。

## 验收分级
- **A（必过，门禁）**：`tests/test_interactive.py` 15 例全绿——
  - **bump-to-attack**：移动目标格有怪 ⇒ 调 `player_attack`、怪物 HP 下降、渲染不改写状态（#8）；
  - **无效键不耗回合**：撞墙 / 未知键 / `?` / `q` 均 `acted=False`（不扰动随机序列，#2）；
  - **核心动作**：拾取 / 用纳米强化剂（伤害加成上升）/ 等待 / 手电开关 / 蛛网突袭未察觉目标 / 下潜 行为正确；
  - **循环结局**：最终层清场 ⇒ `win`、玩家 HP 归零 ⇒ `dead`、`q` ⇒ `quit`；
  - **确定性（不变量 #2）**：同 seed + 同按键序列 ⇒ 同结果（`test_determinism_same_keys_same_result`）；
  - `python scripts/gate.py` 四道门 ALL GREEN，棘轮 506 → 521。
- **B（建议）**：`python scripts/balance_check.py` 默认 30/30、潜行 28/30（与 M20 逐字节一致，无回归，交互模式不影响 demo）；
  `python main.py --play` 可在终端手动操作、地图与状态实时刷新、随时按 `?` 查看操作说明；
  `python main.py`（无 `--play`）演示与 M20 逐字节一致（零回归）。

## 范围边界
- **只加控制层，不改玩法内核**：`_handle_key` / `_player_interactive` 全部调用 `Game` 既有公开方法，
  不新增任何随机、不修改 `src/rogue/*`（熔断②友好，既有 506 例零回归）。
- **move 保持 4 向**（与 M1 网格一致）：避免斜向穿墙角破坏不变量 #4；方向键原始转义序列也纳入映射，
  但默认用 `input()` 读取，WASD / hjkl 始终可用。
- **bump-to-attack**：`move` 遇怪返回 False（M2 不可穿怪），交互层据此改调 `player_attack`；
  不改写 `grid` 以外状态（#8 延伸）。
- **回合模型与 demo 一致**：有效动作消耗一个回合（随后 `monster_turn`），无效/纯信息键不消耗 ⇒ 不扰动随机序列（#2）。
- **opt-in（默认关闭）**：`--play` 才进交互；默认仍是脚本自动驾驶 demo，`main()` 其余分支一字未动 ⇒ 行为零回归。
- **交互专用动作未覆盖的部分**（留作后续细化，非 M21 阻塞）：
  M14/M16/M19 的「射灭/射碎房间灯（或墙边开关）」需要选定目标房间，交互模式暂未做目标选择 UI，
  仍是 demo 自动战术；M9 垃圾桶盖在交互模式按 `1~5` 触发时复用 demo 的 `_decoy_spot` 自动选最优落点。

## 不变量增量
- **#21 可键盘操作**：玩家经 `main._player_interactive` 键盘控制；`_handle_key` 只调用 Game 既有确定性方法，
  不引入任何随机 ⇒ #1/#2 不变；与脚本自动驾驶 demo（`_player_act`）共用同一套 Game 方法、互不影响（默认无 `--play` 仍走 demo，零回归）；
  撞怪即攻击（bump-to-attack，不改写 `grid` 以外状态，#8 延伸）；有效动作消耗一个回合、无效/纯信息键不消耗（不扰动随机序列，#2）；
  相同 seed + 相同按键序列 ⇒ 相同结果（#2，机器判定 `tests/test_interactive.py`）；move 保持 4 向（#4）；`--play` 为 opt-in。
